# Cross-checking pgmpy against reference implementations

## Overview

pgmpy's results should match established implementations on the same input. A test whose expected values came from
pgmpy itself only checks that the output didn't change, not that it is right.

## Which reference

| Area | Reference |
|---|---|
| Structure scores, parameter learning, BN file formats, example models | bnlearn (R) |
| Constraint-based discovery (PC, FCI), CI tests | pcalg (R), causal-learn, bnlearn |
| Kernel CI tests (KCI, HSIC) | causal-learn |
| d-separation, adjustment sets, implied independencies | dagitty (R, or dagitty.net) |
| ADMGs, latent projection, identification (ID) | ananke, causaleffect (R) |
| Causal effect estimation | DoWhy, DoubleML |
| Estimator API conventions | scikit-learn |

## Running a reference without changing the dev environment

- **Python:** `pip install --target <scratch>/deps --no-deps <package>`, then run with `PYTHONPATH=<scratch>/deps`.
  `--no-deps` stops the target directory from shadowing the environment's numpy or pandas; install a missing dependency
  the same way.
- **R:** install packages into a scratch library and put it first on the library path, so the user's R library is
  untouched. Write the script to a file and run it with `Rscript`:

  ```bash
  mkdir -p <scratch>/Rlib
  R_LIBS=<scratch>/Rlib Rscript -e 'install.packages("BiocManager", repos = "https://cloud.r-project.org")'
  R_LIBS=<scratch>/Rlib Rscript -e 'BiocManager::install(c("graph", "RBGL", "pcalg"), update = FALSE, ask = FALSE)'
  R_LIBS=<scratch>/Rlib Rscript <script>.R
  ```

  pcalg needs the Bioconductor packages `graph` and `RBGL`. Add bnlearn, dagitty or other references to the same
  `BiocManager::install` call. `update = FALSE` stops it from upgrading packages that are already installed.
- If R or a package is unavailable, say so and use the best available alternative. Never report a cross-check that
  didn't run.

## Comparing

1. Use the same data and the same parameters. Defaults differ between libraries: significance level, equivalent
   sample size or prior, score scale and sign, log base, degrees-of-freedom adjustments.
2. Compare numbers with a tolerance (`np.testing.assert_allclose`, `pytest.approx`), not printed digits.
3. Compare graphs by their edge sets including edge types, not only adjacency.
4. When the libraries differ by design, document why in a test comment instead of loosening the tolerance.

## Recording expected values in tests

Put the reference package, its version and the producing call in a comment above the hard-coded values:

```python
# Reference statistics and p-values from causal-learn v0.1.4.5:
# KCI_CInd().compute_pvalue(df[["X"]].to_numpy(), df[["Y"]].to_numpy(), df[Z].to_numpy())
```

`pgmpy/tests/test_ci_tests/test_kci.py` follows this pattern.

## Known quirks

- ananke 0.5.0: `DAG.latent_projection` creates self-loop bidirected edges (`c <-> c`) that later raise a `KeyError`.
  Project one vertex at a time with `latent_project_single_vertex` and drop self-loops after each step.

## Common mistakes

- Expected values generated by running pgmpy.
- Comparing runs that use different defaults.
- Reporting agreement from a cross-check that couldn't run.
